# K230 热点图传操作手册

比赛部署只使用 `k230_code/k230_final.py` 与 `pc_receiver/pc_receiver.py`。图传仅用于现场显示和录像；钢球闭环只走 K230→Ti 的有线 UART，PC 绝不回传控制数据。

## 当前图传模式：管子细节优先

```text
相机原始采集：640×480 全视场
控制视觉：原图缩放到 320×240，传统 Blob 识别后发送 UART
图传来源：原始图中裁取 (x=0, y=120, w=640, h=240) 的管子带
图传编码：JPEG Q80，目标 8 FPS
PC 显示：640×240 原图以最近邻 2 倍显示（窗口约 1280×480）
```

这一模式不再把 `320×240` 视觉图放大后再推流，因此刻度线保留原始横向 640 像素细节。实机已测得 `Loop 25.7–26.7 FPS`、图传 `6.8–8.2 FPS`、`vis 15.7–16.1 ms`，满足控制循环不低于 20 FPS 的基线。

## 启动

1. 打开 Windows 2.4 GHz 热点，SSID/密码仅用英文、数字和常见符号。
2. 先在 PC 的 `dev` 环境运行：

```powershell
python C:\Users\sznnn\Desktop\26-dian-sai\pc_receiver\pc_receiver.py
```

3. 检查 `k230_code/k230_final.py` 中 `WIFI_SSID`、`WIFI_PASS`、`PC_IP` 与热点一致，然后烧录该文件为 K230 的 `/sdcard/main.py`。
4. K230 正常启动时应看到：

```text
[K230] Camera 640x480 OK
[K230] Vision full-FOV 640x480 -> 320x240
[K230] Video pipe ROI (0, 120, 640, 240) -> 640x240 Q80 @8fps
[K230] PC video receiver connected
```

PC 端按 `r` 开始/停止录像、按 `q` 退出。必须看到 `Recording finalized` 后，MP4 才已完整封装；不要直接结束 VS Code 终端进程。

## 首次实机验收

保持管子处于中位，运行 30–60 秒，记录并反馈：

- PC 窗口截图：确认完整管段、边缘刻度和钢球都清晰；
- PC 实际 FPS；
- K230 稳态连续 5 行日志（含 `Loop`、`Video`、`cap/vis/enc/net`）；
- 是否出现 `video socket stalled`、画面裁切或明显卡顿。

通过基线：PC 约 8 FPS、刻度可辨，且 K230 `Loop` 不低于 20 FPS。图传断开时，UART 和视觉仍必须继续运行。

## 调整顺序

1. 若 `Loop < 20 FPS`，先把 `pipe_detail` 配置的目标帧率从 `8` 改为 `6`；不要先降低 640 像素宽度。
2. 若管子在 ±8° 时被裁切，只调整 `PIPE_VIDEO_CROP` 的 `y/height`，保持 `width=640`；调整后重新记录性能。
3. 若源图本身刻度仍糊，优先手动调焦至管子平面、固定相机、补充均匀漫反射照明。JPEG 质量或 PC 放大不能恢复已经失焦的原始细节。
4. 若出现 `Video pipe ROI canvas failed`，程序会自动尝试 `copy(roi)` 保留 640×240 细节；只有它也失败时才回退到低清视觉图。保留完整异常和启动日志。
5. 若出现 `video socket stalled`，检查 PC 接收端、热点距离和电脑省电策略；它不应影响 UART 控制。

## 已知路线边界

当前 Yahboom CanMV v1.4.3 的双通道硬件 VENC/H.264 探针会报 `Sensor.buf_init`，不要设置 `VIDEO_BACKEND="h264_hw"`。若后续更换为兼容固件或转入 K230 SDK 工程，可再评估硬件 H.264/H.265 + RTSP；这属于独立升级，不阻塞当前的 CPU JPEG 管子细节图传。
