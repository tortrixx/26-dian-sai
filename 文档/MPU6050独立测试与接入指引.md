# MPU-6050 独立测试与接入指引

> 更新日期：2026-07-30。本文是目前角度传感器工作的唯一交接入口；它将“已被硬件验证的事实”和“仍未开始的摆杆闭环”明确分开。

## 1. 当前结论

原 **LP-MSPM0G3507 LaunchPad** 已通过 USB/XDS110 完成 MPU-6050 独立点亮测试。传感器在 I²C 地址 `0x68` 正常应答，`WHO_AM_I` 返回 `0x68`，唤醒后可连续读取加速度计和陀螺仪的原始数据。

这证明以下链路可用：**MPU-6050 供电 → PB2/PB3 I²C → MSPM0G3507 → XDS110 调试串口**。测试工程没有驱动 MG996、车体电机或 K230；因此不能把本次结果解读为摆杆已闭环、角度已校准或 LQR 已可用。

## 2. 已验证硬件与接线

目标板是原 LP-MSPM0G3507，不是 MSP-LITO-G3507。成功测试时使用的连接如下：

| MPU-6050 引脚 | LP-MSPM0G3507 连接 | 作用 | 已验证 |
| --- | --- | --- | --- |
| `VCC` | `3V3` | 模块供电 | 是 |
| `GND` | `GND` | 公共参考地 | 是 |
| `SCL` | `PB2 / I2C1_SCL`（LaunchPad Header 9） | I²C 时钟 | 是 |
| `SDA` | `PB3 / I2C1_SDA`（LaunchPad Header 10） | I²C 数据 | 是 |
| `INT` | 不接 | 本测试使用轮询，不需要中断 | 不适用 |

模块上额外的 `XDA`、`XCL`、`AD0` 不参与本次测试。`AD0` 未接时地址为 `0x68`；若将其拉高，地址会变为 `0x69`，而测试程序会依次尝试这两个地址。MPU-6050 只需一根 GND 线；舵机独立电源接入时，舵机电源 GND、Ti GND、K230 GND 必须共地，但不得用 Ti/K230 的小电源给 MG996 供电。

## 3. 可复核的测试证据

| 项目 | 实测结果 |
| --- | --- |
| 调试器 | 已识别 `XDS110 Class Debug Probe` |
| 串口 | 已识别 XDS110 Application/User UART，当前电脑为 `COM5`（其他电脑可能变化） |
| 烧录 | `DSLite load` 已成功完成并启动程序 |
| I²C 身份 | `WHO_AM_I=0x68 address=0x68` |
| 运行输出 | 连续收到 `a=ax,ay,az g=gx,gy,gz` 原始数据；移动模块时数据变化 |

串口启动信息应为：

```text
MPU6050 I2C test: PB2=SCL PB3=SDA
WHO_AM_I=0x68 address=0x68
PASS: MPU awake. Move the board; ax/ay/az/gx/gy/gz must change.
```

注意：原始数值不是角度，也不是 SI 单位；尚未做零偏、比例或安装轴方向校准。静止时三个加速度分量的平方和应接近 1 g，但具体落在哪个轴取决于模块安装方向。

## 4. 代码架构与边界

```text
K230 本地视觉 ──有线 UART──> 正式 MSPM0 控制工程 ──PWM──> MG996 / 摆杆
                                      ↑
                                      │ I²C1: PB2/PB3
                                      │
                                  MPU-6050

ti_reference/firmware_state_machine_skeleton.c
  └─ UART、球位置 PD、安全状态机的逻辑参考；尚未接入真实 Ti 工程

ti_mpu6050_test/
  └─ 独立 I²C 点亮和原始数据读取；已验证，不能直接驱动执行器
```

| 位置 | 职责 | 当前状态 |
| --- | --- | --- |
| `k230_code/k230_final.py` | 钢球识别、位置标定、向 MSPM0 发送有线 UART 观测 | 已部署入口 |
| `ti_reference/firmware_state_machine_skeleton.c` | 视觉帧校验、100 Hz 球位置 PD、超时回中位的参考逻辑 | 未接入芯片工程 |
| `ti_mpu6050_test/msp_mpu6050_test.c` | MPU-6050 地址探测、唤醒和原始六轴数据打印 | 已在硬件上通过 |
| `ti_mpu6050_test/msp_mpu6050_test.syscfg` | I2C1 `PB2/PB3`、调试 UART0 `PA10/PA11` | 已在硬件上通过 |

不要把调试 UART0（XDS110 的 PA10/PA11）误接为 K230 控制 UART；正式 K230→MSPM0 的 UART 引脚和驱动应由正式 Ti 工程单独选择、配置和验证。

## 6. 下一位开发者的推荐执行顺序

### 阶段 1：将“原始数据”变成可信摆杆角度

1. 将 MPU-6050 **刚性固定到摆杆**，而不是固定在车架；记录芯片 X/Y/Z 轴与摆杆转轴的对应关系。
2. 静止采样至少 2 秒，计算陀螺仪零偏；分别将摆杆置于已知 `-8° / 0° / +8°`，确认加速度计算的倾角方向与实际一致。
3. 以加速度倾角进行低频校正、以陀螺仪角速度进行短时预测，先实现互补滤波。只有在振动明显、滤波参数难以满足时，再考虑卡尔曼滤波。
4. 记录“传感器角度 → 实际摆杆角度”的零点、符号和安装偏差；这张表比立即上 LQR 更重要。

建议正式接口独立为 `mpu6050_init()`、`mpu6050_read_raw()`、`attitude_update(dt)` 和 `attitude_get_pipe_deg()`，并让 100 Hz 控制任务只读取最后一个已经滤波的角度值。I²C 读取失败必须计数并转入安全处理，不能继续使用陈旧数据无限控制舵机。

### 阶段 2：先做安全的双层控制，再评估 LQR

当前舵机本身已有位置闭环；正式控制应先采用：**钢球位置 PD 外环**输出目标摆管角度 `theta_ref`，再用 MPU-6050 的 `theta` 做摆角误差限制/校正。首版保持 `Ki=0`、摆角 `±8°`、角速度限制、视觉 200 ms 超时回中位和 I²C 失效回中位。

LQR 不是当前第一步：它需要确定状态向量、采样周期、摆管—球动力学参数、舵机实际响应和状态噪声。没有这些标定时，直接套增益会降低可控性。先让位置 PD + 实测倾角稳定通过 `-5/0/+5 cm` 静态测试，再采集输入角度、球位置和速度数据，才有条件辨识模型并比较 LQR 是否带来收益。

### 阶段 3：接入正式 Ti 工程

1. 先按 [控制接口骨架](控制接口骨架.md) 合入 UART 校验、100 Hz 调度、超时回中位和 MG996 PWM。
2. 将本测试的 I²C/滤波模块移入该工程；保留调试输出，但避免阻塞 100 Hz 任务。
3. 无球状态依次验证：舵机中位、方向、机械限位、MPU 角度方向、I²C 失效、K230 停止、UART 拔线。每一种异常都必须安全回中位。
4. 最后才完成相机最终五点标定，并开始静态球位置 PD 调参。完整装配顺序仍以 [下一阶段装配与联调清单](下一阶段装配与联调清单.md) 为准。
