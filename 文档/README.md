## 1. 今日最终结论

单摄像头方案已完成并实测：GC2093 保持 `640×480` 全视场采集；K230 在内部缩放为 `320×240` 做传统视觉和 UART 控制，同时从**原始帧**裁取 `640×240` 管子带做 JPEG 图传。

| 项目 | 最终值 | 实机证据 |
| --- | --- | --- |
| 图传图像 | 原始管子 ROI `640×240`、JPEG Q80、目标 8 FPS | 刻度清晰度已提升；K230 实测 Video `6.8–8.2 FPS` |
| 视觉控制图 | `320×240`，亮/暗 Blob、形状门限、α-β 跟踪 | 有效钢球质量 `75–86` |
| K230 循环 / UART | `25.7–26.7 FPS` | 每处理帧发送一次 UART 观测 |
| 性能分解 | capture `3.8–4.3 ms`、vis `15.7–16.1 ms`、enc `10.6–12.3 ms`、net `0.5–0.8 ms` | Wi‑Fi 不是瓶颈 |
| 钢球 | 正常未喷涂 1 cm 钢球 | 台架五点已初标定；最终装车后必须复标 |

该结果满足“清楚观察刻度”和“控制循环不低于 20 FPS”两项当前基线。它**不等于**摆管闭环已经完成；Ti/MG996 机械、供电、安全保护和 PD 调参尚未开始实车验证。

## 2. 当前可部署配置

文件：`k230_code/k230_final.py`

```text
VISION_PROFILE      = fast_qvga
capture             = 640×480 full FOV
vision              = 320×240
STREAM_PROFILE      = pipe_detail
pipe video crop     = (0, 120, 640, 240)
video               = JPEG Q80, target 8 FPS
VIDEO_BACKEND       = jpeg_cpu
UART                = UART1, IO9 TX / IO10 RX, 115200 8N1, 3.3 V TTL
```

文件：`pc_receiver/pc_receiver.py`

```text
TCP listen port     = 8888
display             = 2× nearest-neighbour (保留刻度像素边缘)
recording           = PyAV/libx264 MP4, 8 FPS
```

Wi‑Fi 仅用于赛外实时显示与录像；闭环唯一数据链是 K230→Ti 的车内有线 UART。PC 不得回传任何控制信息。

当前测试热点参数已按仓库所有者授权保留在 `k230_final.py`，可直接用于现有环境；若热点名称、密码或 Windows 网关变化，修改该文件中的 `WIFI_SSID`、`WIFI_PASS`、`PC_IP` 后再烧录。

## 3. 今天的开发历程与关键决策

1. **早期低清图传的问题**：原方案先把全视场缩小到 `320×240` 做视觉，再将这张小图 JPEG 推送到 PC。即使提高 JPEG 质量或把 PC 窗口放大，管口刻度也已经被缩小丢失，无法恢复。
2. **不采用 YOLO**：钢球是普通未喷涂钢球；采用 L 亮度自适应亮/暗 Blob、面积、长宽比、圆度、位置预测和 α-β 跟踪。方案轻量，可在 K230 上本地运行。
3. **不采用当前固件的硬件 H.264**：Yahboom CanMV v1.4.3 双通道 VENC 探针调用 `Sensor.set_framesize()` 会报 `Sensor object has no attribute buf_init`。因此禁止在本固件上启用 `VIDEO_BACKEND="h264_hw"`。
4. **图传质量提升的正确做法**：保持控制视觉 QVGA 不变；从原始 640×480 帧直接取 640×240 管子带，再 Q80 JPEG 编码。PC 使用 2×最近邻显示，避免普通线性缩放抹平一像素刻度。
5. **第一次细节图传瓶颈**：Q80 细节图传刚提升到目标 8 FPS 时，实际 Video 仅约 6.6 FPS、`Loop` 降到 17–18 FPS。日志显示 `net<1 ms`，故不是热点问题。
6. **最终性能优化**：稳定跟踪时，上一帧已经知道钢球呈亮还是暗。代码只先跑对应极性的 `find_blobs()`；质量低于 65 或未命中则在**同一帧**补跑另一极性。因此保留反光变化/重捕获能力，同时将 `vis` 从约 30 ms 降至约 16 ms，`Loop` 回升至 25.7–26.7 FPS。

## 5. 下一个 agent 的推荐接手顺序

### 第一步：先读、先核对

1. 阅读本文件、`后续TODO清单.md`、`下一阶段装配与联调清单.md`。
2. 执行 `git status --short --branch`，保留用户现有改动；不要使用 `git reset --hard`。
3. 只修改 `k230_code/k230_final.py` 作为 K230 比赛入口；历史脚本只用于查阅或孤立诊断。

### 第二步：机械、电源、Ti 的无球联调（当前主线）

1. 完成左侧铰点摆管、MG996 连杆、端部防落球与相机刚性支架。
2. 舵机使用独立大电流电源；K230、Ti、舵机电源只共地，严禁从 Ti/K230 小板供电端驱动 MG996。
3. 先在无球状态接入 Ti：100 Hz 控制任务、50 Hz PWM、舵机中位、正负方向、±8°限幅和角速度限制。
4. 完成停止 K230、拔 UART、坏校验帧、连续无效帧时 200 ms 内限速回中位的测试；图传断连不得影响 Ti 行为。

### 第三步：最终视觉复标与鲁棒性验收

1. 相机最终固定后，先查看 `-8° / 0° / +8°`；若图传裁切到管子，仅改 `PIPE_VIDEO_CROP` 的 `y/height`，保持 640 宽度。
2. 按 `-10/-5/0/+5/+10 cm` 收集每点 60 个有效观测，更新 `POSITION_CAL_PX`、面积门限、`PIPE_ROI` 和活动带。
3. 在无球、反光、遮挡、轻振动下测试。若稳定跟踪出现异常，可临时设 `TRACK_POLARITY_FAST_PATH = False` 恢复每帧双极性搜索，用结果定位问题后再优化。
4. 先 `Ki=0`，按 `Kp → Kd` 调整静态 `-5/0/+5 cm`；静态通过后才开放动态 AB，再开放整圈。

## 6. 不要做的事

- 不要使用 YOLO、PC 图像处理回传、摄像头循迹或管壁传感器/色标；它们不符合本项目选择或题目约束。
- 不要将 `VISION_PROFILE` 改为 `vga_precision` 来换取视觉精度；它会显著降低循环率且必须重新标定。
- 不要提高 640×240 图传分辨率、JPEG 质量或目标 FPS 来换取主观画质，除非同时记录 `Loop`。控制循环低于 20 FPS 时，先降 `pipe_detail` 的目标 FPS 至 6。
- 不要启用 `h264_hw` 或反复运行 `k230_h264_dual_stream_probe.py`；该板卡/固件组合会遗留已初始化 Sensor，之后需软重启才能恢复。
- 不要强制结束 PC 接收端进程。录像必须按 `r` 停止或 `q` 退出，看到 `Recording finalized` 后 MP4 才完整。
